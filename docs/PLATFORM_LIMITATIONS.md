# Platform Constraints & Engineering Reality Matrix

Linkora prioritizes technical honesty and data security over deceptive marketing. Operating system sandboxes enforce strict boundaries that cannot be bypassed legally or reliably. This document details each constraint, what Linkora implements, and why alternative "workarounds" were rejected.

---

## 1. macOS Login Screen vs App-Level Biometric Approval

| Claim | Reality | Linkora Implementation |
| :--- | :--- | :--- |
| "Unlock your Mac login screen from an Android phone or iPhone" | ❌ **Blocked by Apple Security Model**. Modern macOS (Ventura, Sonoma, Sequoia) protects the native `loginwindow` and FileVault inside a dedicated Mach bootstrap namespace protected by SIP (System Integrity Protection). No public API exists for non-root processes to unlock FileVault. | ✅ **App-Level Session Lock & Gating**. Linkora creates a cryptographic gate protecting user files, clipboard, and apps, requiring hardware-signed nonces via Face ID / Android BiometricPrompt. It triggers native screen lock via `SACLockScreenImmediate`. |

### Dangerous Workarounds Rejected:
1. **Plaintext Password Storage**: Storing the Mac user password on the phone and auto-typing it. If the phone or transmission is intercepted, the attacker gains full root access to the Mac.
2. **PAM Injections (`/etc/pam.d/authorization`)**: Fragile C plugins running in the authorization daemon frequently crash macOS after minor OS updates, locking users out of their computers.

## 2. Camera as Mac Webcam (In-App vs System-Wide)

| Capability | Reality | Linkora Implementation |
| :--- | :--- | :--- |
| **In-App Camera Viewer** | ✅ **Fully Supported**. High-speed 1080p 60FPS JPEG/H.264 streams over local TCP sockets. | ✅ Full high-resolution viewer with front/rear lens switching, torch control, and document scanner mode. |
| **System-Wide Virtual Webcam** (Zoom, Teams, FaceTime) | ⚠️ **Requires CMIOExtension Driver**. Starting in macOS 12.3, legacy DAL plugins (`/Library/CoreMediaIO/Plug-Ins/DAL`) were deprecated in favor of `CMIOExtensionProvider`. Creating a virtual camera visible system-wide requires an Apple Developer ID certificate with the `com.apple.developer.coremediaio.camera-provider` entitlement. | ✅ Includes the architectural specification and driver scaffold for `CMIOExtension`. The Mac app checks for driver installation and transparently informs the user if in-app viewer mode is active. |

## 3. Universal Clipboard Synchronization

| Platform | Background Behavior | Linkora Implementation |
| :--- | :--- | :--- |
| **macOS** | ✅ **Unrestricted**. Background daemon monitors `NSPasteboard` changeCount. | Automatic sync with SHA-256 deduplication and loop prevention. |
| **Android 10+** | ⚠️ **Background Clipboard Access Restricted**. Android 10+ prevents background apps from reading the system clipboard (`ClipboardManager.getPrimaryClip()`) unless the app is the default Input Method Editor (IME). | Syncs whenever Linkora is foregrounded, or via a Quick Settings Tile / Share Sheet. |
| **iOS 14+** | ⚠️ **Strict User Notification & Background Suspension**. iOS displays a prominent toast ("Linkora pasted from MacBook") and blocks background apps from accessing `UIPasteboard`. | Operates when the app is active, through the Linkora Action Extension in the iOS Share Sheet, or via interactive widgets. |

## 4. Notification Mirroring

| Platform | Notification Interception | Linkora Implementation |
| :--- | :--- | :--- |
| **Android** | ✅ **Full Mirroring Supported**. Android provides `NotificationListenerService`, allowing user-approved apps to receive notification title, text, icon, and action intents. | Real-time forwarding of Android app notifications directly to macOS banners. |
| **iOS** | ❌ **Prohibited by Apple Sandbox**. Third-party iOS apps cannot intercept notifications generated by other apps (e.g. WhatsApp, Slack, Messages) under any public API. | Linkora truthfully reports this restriction. On iOS, only direct Linkora peer alerts and background transfer push notifications are delivered. |
